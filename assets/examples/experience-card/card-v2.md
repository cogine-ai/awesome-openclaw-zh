## v1 · 2026-10-23

### 核心要点
仓库里有文档，网站上也要给读者一个能打开的入口。

### 机理
内容仓库的文件路径和网站发布路径不同。没有映射到网站的研究文档，可以通过固定提交的 GitHub 链接提供访问入口。

### 具体方法
1. 分别查看内容文档中的链接和网页上的最终链接。
2. 区分仓库文件路径与网站发布路径。
3. 为仓库文档选择对应提交的 GitHub 地址。
4. 打开链接，确认内容与当前教程相符。

### 使用范围·适用
内容仓库与网站发布范围不同，需要让读者找到对应版本文档的知识站点。

### 使用范围·不适用
已经有有效站内页面时，优先保留站内导航；页面搬迁时，可用重定向衔接旧入口。

### AI 补充与提炼
> 固定提交链接有助于让教程与引用文档保持同一版本。
> 排查时从读者实际点击的入口开始，逐步定位路径差异。

## v2 · 2026-10-23

> 变更：加入文件、链接、版本三个检查层次，让排查方法更具体。

### 核心要点
修链接时，同时检查读者能不能打开，以及打开的是不是这版内容。

### 机理
文件层：确认仓库中存在目标文档。
链接层：检查网页实际使用的 href，选择可访问的入口。
版本层：让引用指向与当前教程相符的提交和文档。

### 具体方法
1. 保留 v1 的链接分类。
2. 对照 Markdown 的相对链接与网页最终链接。
3. 打开 GitHub 目标，核对提交和文档内容。
4. 修正入口后，再从读者路径点击一次。
5. 一并检查文中使用的锚点和查询参数。

### 使用范围·适用
内容仓库与网站发布范围不同，需要让读者找到对应版本文档的知识站点。

### 使用范围·不适用
对于需要登录、动态生成或跨域跳转的页面，还要结合其访问方式排查。
