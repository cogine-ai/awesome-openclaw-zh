# 2026-10 增长执行与判断

本轮优先目标是尽快获得真实的仓库关注，同时在有价值的内容旁建立 Cogine 维护者认知。用首批新玩法和可查看的产物形成发布理由；以新内容验证方向，下一轮再扩充表现较好的题材。

## 基线与判断边界

用户提供的最近七天截图：237 visitors（+72%）、299 page views（+114%）、95% bounce rate，约 1.26 PV/visitor。2026-10-11 仓库 API 快照为 240 Stars、37 Forks；最近七天仍保留的 Star 记录仅 1 条，它不包含取消收藏，所以不能当作净增长。

Vercel 的 bounce 是只访问一页的会话，不能由此断言读者没看文章。阅读完成后去 GitHub 收藏、进入外部工具也可能仍是 bounce；自定义事件也不改变该定义。依据：[Vercel Analytics 指标定义](https://vercel.com/docs/analytics)。截图未提供访客来源、阅读行为和出站点击，本轮不做页面改版的效果归因。

## 已落地的路径

1. 网站首页和 `/updates/` 展示最新案例，文章有相关案例与复制/分享入口。
2. 在首页、导航和文章末尾提供明确的 Star 收藏入口，统一指向主内容仓库。
3. 署名与页脚连接 Cogine，让读者能够确认是谁维护这些内容。
4. README 展示网站与更新，Issue 表单接受案例投稿和失效反馈；JSON 目录生成索引，并新增检查防止漏录与数量漂移。当前仓库 Actions 关闭，本轮检查在本地执行通过，尚未启用远端工作流。
5. 发布包提供一篇首发文章、开发者社区短稿、三条短内容和演示脚本。先展示具体产物，保留来源与验证状态。

## 七天只看几项有用的指标

| 指标 | 记录方式 | 能回答什么 |
|---|---|---|
| 仓库净增 Star | 发布前后相同时间读取总数 | 这次更新是否带来收藏增长；不能独立归因到网站 |
| `repo_click` | 网站按页面与入口位置记录 | 哪些内容与入口把读者带到仓库；不等于已 Star |
| `copy_success` / `share_success` | 浏览器实际操作成功后记录 | 哪些案例有人准备尝试或分享；不等于任务跑通 |
| `related_case_click` | 文章相关内容点击 | 阅读者是否继续探索 |
| `company_click` | Cogine 署名/入口出站点击 | 是否带来公司探索；不等于注册或产品使用 |
| 跑通/失效反馈 | Issue 或用户主动反馈，保留版本与产物 | 哪些案例值得继续投入与修复 |

自定义事件需要 Vercel 支持的计划；不支持时先记录仓库总量、站点现有来源和用户反馈，不把“事件代码存在”当成后台已有数据。细节在网站的 `docs/growth-measurement.md`。

首轮七天新增 10—20 Stars 是实验目标。样本仍小，按总量和具体反馈判断，避免用单日波动宣称显著效果：

- 若某个案例带来收藏、分享或跑通反馈，下周围绕它补一个更容易展示的实际产物和第二个变体。
- 若有阅读和复制但反复失败，优先修复步骤、前置条件与版本，再继续宣传。
- 若有访问但几乎没人点击或复制，重新检查选题、标题、最小输入与入口；不用增加几十篇相似内容掩盖问题。

发布动作及分渠道草稿见[发布包](./2026-10-launch-kit.md)。这是人工执行计划，尚未对外发帖或建立定时任务。
