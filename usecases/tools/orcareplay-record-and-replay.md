# 录下一次 OpenClaw 运行，第二天离线复现

> 夜里 Agent 做错了事，白天不用再花一次 token 就能把那一次原样跑回来，并且换个模型看谁做得对。

## 这个案例能帮你做什么

- 把「它昨天到底干了什么」从回忆变成证据：录制的是 OpenClaw 与模型之间真实发送和收到的内容，不是事后让 Agent 自己复述。
- 复盘不花钱：回放时不联网、不调模型、不消耗 token，同一段运行想跑几遍跑几遍。
- 从任意一步换模型继续：分叉点之前逐字节一致，模型是唯一变量，所以「换个模型会不会做对」是一次实验而不是一场争论。

## 快速体验版（先跑一轮）

```bash
npm i -g orcareplay
orca record openclaw          # 照常用 OpenClaw，什么都不用改
orca replay last              # 刚才那一轮再跑一遍：不联网、不花钱
```

```text
你是我的 OpenClaw 助手。
我刚刚用 orca record openclaw 录了一轮运行。
请帮我做「录制与离线复现」的预演版：
1. 用一句话说明这一轮你实际做了哪几步
2. 指出其中哪一步最可能是出错的那一步，并说明依据
3. 告诉我要复现这一步，回放时该从第几步开始分叉
4. 本轮不要做任何写入或高风险动作
```

## 稳定自动版（可长期运行）

### 1) 配置或脚本片段（可选）

```bash
# 录制：适配器会挂 OpenClaw 网关的钩子，并把变量传给它拉起的子 Agent
orca record openclaw

# 回放：按录制内容逐字节返回，不联网
orca replay last

# 从第 4 步换模型继续（第 4 步之前与原运行完全一致）
orca replay last --from 4 --model claude-haiku-4-5 --ui
```

### 2) OpenClaw 执行提示词（自动版）

```text
你是我的 OpenClaw 助手，请执行「录制与离线复现」。

执行步骤：
1. 读取最近一次录制，按时间顺序列出每一步的动作与结果
2. 标出第一处结果与预期不符的步骤，并给出判断依据
3. 给出该步骤的分叉命令（orca replay last --from N --model <模型>）
4. 汇总为一段可以贴进复盘记录的说明
```

## 成功标准（可选）

- [ ] `orca replay last` 跑完时报告有多少轮由录制提供、其中多少轮完全一致
- [ ] 回放过程中没有对模型服务发起任何请求

## 风险与边界（可选）

- **回放一致不等于确定性结论**：它证明录下来的那次交换能复现，不证明 Agent 是确定性的，也不证明真去调模型还会同样失败。
- **回放只挡模型侧出口，它不是沙箱**：录进去的工具调用在回放时是真执行的——录了一条会删文件或会联网的命令，回放时它照样删、照样联网。所以回放要在你当初敢跑原运行的那个环境里做。
- **默认适配器不是所有调用都抓**（例如 embedding 不抓），依赖检索的那一类问题可能回放得很干净却复现不出来。

## 使用建议（可选）

- 先用一轮短的运行验证录制通了，再去录夜间长任务。
- 复盘时先看回放报告里「完全一致」的轮数，不一致的地方往往就是值得看的地方。
- 换模型对比时只改模型这一个参数，别顺手把提示词也改了。
